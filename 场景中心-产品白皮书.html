01 / WHY

为什么需要场景中心

在数据中台与业务系统建设中，流程往往散落在项目、人员与环境之间： 缺少统一归属、难以复用、跨环境迁移成本高。场景中心正是为解决这些问题而生。

痛点一：流程散乱

流程按人、按项目临时堆积，缺少场景与业务域视角，后期难检索、难交接。

痛点二：经验难复用

优秀链路无法沉淀为标准模板，新建时反复从零配置，效率低下。

痛点三：迁移成本高

多环境、多系统、多项目之间缺乏统一的导出导入机制，交付周期被拉长。

场景中心的目标：把「能跑通一次」的业务链路，变成「可复制、可协作、可迁移」的组织资产。

02 / PRODUCT

场景流程

默认入口。按场景管理流程实例：新建、浏览、进入工作台、收藏协作、批量管理。

迁移助手

03 / VALUE

核心价值与典型旅程

1

可见：场景即入口

只有场景下已有流程时才展示场景卡片，列表始终聚焦「有资产的场景」。价值描述帮助团队说明方案意义。

2

可建：新建即闭环

新建流程时先定所属场景，再填名称与创建方式；支持自定义添加场景与业务域，降低冷启动门槛。

3

可复用：定义驱动标准

在流程定义中沉淀标准开发流程并上线后，新建时可直接「使用操作模板」，减少重复配置。

4

可迁移：场景级导出

在场景卡片点击「导出此场景」，即可写入迁移助手导出记录，支撑多环境、多项目流转。

四条典型业务旅程

旅程 A · 从零建设

缺省页 → 新建流程 → 选择/添加场景与业务域 → 进入工作台 → 保存回场景列表

旅程 B · 场景运营

场景列表 → 查看全部流程 → 按业务域分组管理 → 收藏/协作/批量维护

旅程 C · 模板提效

流程定义上线模板 → 新建流程选用模板 → 快速进入标准开发链路

旅程 D · 跨环境交付

导出此场景 → 迁移助手查看记录 → 新建迁出/迁入 → 完成资产流转

04 / HIGHLIGHTS

产品亮点拆解

亮点 1：场景列表即资产门户

  • 场景卡片聚合业务域、流程数量与价值描述
  • 「查看全部流程」「导出此场景」一站完成运营与交付动作
  • 业务域小卡支持直达域内流程，缩短查找路径

亮点 2：新建流程以场景为第一归属

  • 表单优先填写所属场景，避免「先建后归类」
  • 支持自定义添加场景与业务域，边建边扩展目录
  • 创建方式支持空白开工或模板启动，兼顾灵活与标准

亮点 3：全部流程页的高效浏览

  • 面包屑清晰回退：场景流程 / 场景 / 全部流程或业务域
  • 按业务域分组，顶栏「全部展开 / 全部收起」一键切换
  • 全部、收藏、协作筛选 + 名称搜索，快速定位目标流程

亮点 4：定义与实例分层治理

  • 流程定义负责「标准母版」
  • 场景流程负责「落地实例」
  • 上线模板自动进入新建可选范围，形成治理闭环
